# Dance v0.3.1

This patch improves embedded ACME readiness reporting, cancellation handling and
failure diagnostics.

## Changes

- `/readyz` performs a non-mutating storage read with a one-second timeout. It
  returns 503 during observed ACME request stalls or recent server errors. A
  successful nonce or directory request does not clear an order failure.
- Canceled account-registration requests stop waiting for the enrollment lock.
  Active transactions continue to preserve atomic account/EAB writes.
- Embedded ACME responses include `X-Request-ID`. Server logs correlate request
  operations, status, duration and safe underlying storage error classes. Slow
  requests produce a warning after five seconds.
- Regression coverage includes repeated signed order/authorization requests,
  concurrent health probes and real Caddy issuance and renewal with a persisted
  account. Caddy 2.6.2 and 2.11.9 passed local verification.

`/healthz` remains a liveness check. Readiness does not issue certificates, test
storage writes or guarantee renewal. Continue monitoring certificate expiry and
ACME client failures.

## Deployment

Back up the Dance and CA databases, then replace the binary or deploy
`ghcr.io/rcarmo/go-dance:v0.3.1`. Keep the existing CA configuration, database
volumes, provisioner identities, API credentials and ACME account storage.
No account or EAB reset is required.

If ACME requests fail, collect the UTC timestamp, response `X-Request-ID` and
matching `acme_request`, `acme_error` and `acme_storage` server log entries.
Include the deployed image digest or binary build identity. Do not include EAB
HMACs, bearer credentials, private keys, signed request bodies or challenge tokens.
See the [operations guide](https://github.com/rcarmo/go-dance/blob/v0.3.1/docs/operations.md)
for health-check semantics and diagnostic steps.

The reported intermittent NAS nonce/order failure has not reproduced in the
isolated tests. Its root cause remains unconfirmed; this release supplies the
verified fixes and diagnostics needed for deployment investigation.

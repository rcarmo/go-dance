# Dance v0.2.6

Uses one `default` ACME provisioner in the sample configuration and fixes landing-page directory URLs to follow configured provisioner names. Go 1.27.3, third-party dependencies and persistence formats are unchanged from v0.2.5.

## Fixes

- Replace the sample's `acme` and separate `acme-eab` entries with one ACME provisioner named `default`. Enable `requireEAB` on that same provisioner when enrollment tokens are required; the primary sample's existing EAB policy is otherwise unchanged.
- Use `/acme/default/directory` in the bootstrap and Caddy examples.
- Generate the landing-page directory URL and Caddy snippet from configured provisioners. Prefer `default` when present; otherwise use the first configured ACME provisioner. Preserve existing names such as `acme` and custom names, and escape names in the URL.
- Stop guessing a directory URL when provisioner information is unavailable, including external proxy mode.
- Add regressions for the single-default sample, default/legacy/custom provisioner names, matching display/snippet URLs and actual embedded-authority landing-page URLs.
- Align the Nix package version with v0.2.6.

## Upgrade and existing CA identities

This changes the repository sample and UI; it does not rename provisioners in a deployed CA or migrate stored IDs, accounts or EAB keys. If an existing CA is named `acme`, continue using `/acme/acme/directory`; the UI now displays that configured name correctly. Only use the URL below after configuring a provisioner named `default`:

```caddyfile
acme_ca https://diskstation.local:8443/acme/default/directory
```

Keep existing provisioner identities unless an operator deliberately plans their state migration. No live CA configuration or private keys were modified during release preparation.

## Release policy

Linux AMD64 and ARM64 binaries/images use matching native Linux runners. Windows binaries are cross-compiled on those Linux runners. Darwin targets remain omitted to save GitHub Actions costs; no Darwin or Windows runners are used. Apple certificate-enrollment support is unchanged.

The security fixes and persistent production-session-key requirements from v0.2.5 are retained. No new application features were added.
